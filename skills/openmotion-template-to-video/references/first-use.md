# First-run template experience

Read only after the user accepts the installation experience with a selected editable template. The installation welcome remains in docs/install-onboarding.md.

## First-run experience defaults

Installation opens the editor template library first, without creating a project, following `docs/install-onboarding.md`, section “Installation-success reply”. Browsing and previewing do not authorize creation. This contract applies after the user explicitly asks the Agent to create with a selected template ID/name. Preserve that exact selection and its duration. A generic “yes/体验” without a selected template needs clarification before creation. A refusal/deferment stops. Do not substitute Product Promo or another template, restart intake or repeat optional assets/brand/style questions. If the user already clicked Open and edit in Studio, continue that actual project instead of creating a duplicate.

Use the unchanged sample content and one independent editable project, preserving existing work. Reuse the existing experience project if already created. Otherwise call `openmotion_create_project` once with projectType=template, the exact accepted templateId, stable requestId, title and confirmed requirements. Record the returned projectId. If that template is unavailable or cannot be copied, report the failure without silently replacing it. Call `openmotion_open_preview({projectId})` and open its exact previewUrl through the host's supported browser/panel; check loading and playback. The project is the deliverable; export only when requested.

If the user requested unchanged HTML/project or MP4 files, continue through [unchanged file export](unchanged-export.md), including its bounded handoff and parallel version-pinned work. Modified content uses [verification](../../openmotion-production/references/verification.md); reuse an applicable existing job or call `openmotion_export_request` once with the current projectId/versionId/revision and stable requestId. Poll `openmotion_get_project` with exportJobId; technical verification is automatic, actual playback is separate.

For a successful first-run delivery, keep the editable OpenMotion page open on the right. The final reply contains, in order, one concise completion sentence and the contextual next-step invitation below. Use plain Markdown. Keep screenshots and verification evidence in local records; omit MP4s, editor screenshots, ZIPs, duplicate project links and checklists from this reply unless the user requested them. HTML wrappers such as `<details>` and `<summary>` are not part of the reply format.

After the completion sentence, generate one brief, natural sentence in the user's language asking what video they want to make next and introducing three ways to start: choose an existing template, send a video link to recreate, or describe their requirements for an original video. Adapt the wording to the conversation; this is a behavior instruction, not a fixed script. If the user already supplied their next request, acknowledge or continue that request instead of asking again. Otherwise wait for their choice before starting another video. This invitation belongs only to the first successful experience delivery, not follow-up edits or exports.

If a host lacks browser/panel capability, provide the project URL and briefly state that the page could not be opened automatically. Report any material delivery limitation before inviting new work. If the project cannot be created or does not load and play, or a requested export fails, preserve the editable project and report the concrete failure without a success statement or next-step invitation. If tools are unavailable, carry this selected template/defaults/project scope into a continuation without asking the user to choose again.
