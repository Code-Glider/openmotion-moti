# OpenMotion onboarding

Follow the [shared installation contract](../../docs/install-onboarding.md#installation-success-reply). Open the library and display the maintained welcome and three full-video cards together in one native component. Do not require a separately streamed welcome. Accept automatic current-chat MCP activation independently; registration, a later connected chat and an independent probe do not prove it.

1. **Reuse the installation.** Source setup returns `inlinePresentation`, `preview`, `hostHandoff`, `detailsFile` and, for a known chat, `recovery`. npm setup wraps these in `onboarding`. Preserve the application, workspace, language and frozen random three-of-nine IDs/order. If no setup result exists, run the installed `node --experimental-strip-types scripts/install-onboarding.mjs` once with the connection's workspace and the latest request's `OPENMOTION_ONBOARDING_LANGUAGE`. Never reinstall or enqueue a new user message.
2. **Use the current native connection.** Verify its workspace with `openmotion_get_project`. A working connection can deliver the component even when script host control is missing; do not block it on `hostHandoff` or report presentation as automatic-activation acceptance. If native discovery is missing/stale, use a supported existing-host reload. For `refresh_requested`, finish the current tool step, then run `recovery.command` with `recovery.args` once in this turn. Recovery preserves the selection, resource and workspace without another reload or library startup. Retain a missing-control blocker for separate activation acceptance. Do not start another app-server, change host security, restart Codex, or ask the user to restart a connection as a substitute for automatic activation.
3. **Open the library once.** Use the exact `preview.previewUrl` in this chat's right-hand browser, preserving query parameters and reusing the existing tab. Mark it as a deliverable when required by the browser tool. Opening is sufficient: no template inventory scan, screenshot audit or full-video playback check is needed for installation. Do not create a project.
4. **Deliver the native welcome and video cards together.** For `native_required`, call the natively discovered `openmotion_show_template_recommendations` once with the prepared IDs/order, request language and `onboarding:true`. The persistent component returns the maintained welcome above exactly three full-video cards, without coordinating a separate streamed reply. Do not duplicate it in the final reply, put it only in collapsed commentary, replace videos with text cards, substitute builtins or resample. If the welcome already appeared during the same delivery, append `--welcome-delivered` to recovery and use cards-only `onboarding:false`. Verify the current schema/resource and actual visibility of the combined component. Record presentation evidence separately from automatic activation; actual audiovisual acceptance remains a separate user check.

If native cards cannot be displayed, open the library and make the entire final reply exactly the top-level `welcomeMarkdown`: the three welcome paragraphs defined in the shared contract, with their paragraph breaks. Keep installation status, blockers, links and recovery details in diagnostics and the receipt, outside the reply. Preserve the incomplete onboarding state and frozen selection for recovery.

Self-contained builtin fragments retain the contract's compatibility path; they are not the default nine-reference onboarding and never replace its selected references. A readable prepared file does not prove visible delivery.

Use `zh`, `en`, `ja`, `ko`, `fr`, `es` or `pt` from the latest user request, otherwise `en`. Recreate prepares an unsent draft through a negotiated host extension, or copies the brief with a floating Toast. Only the user-sent brief authorizes creation/export. Continue an accepted recommendation through [accepted template selection](../../docs/install-onboarding.md#accepted-template-selection).
